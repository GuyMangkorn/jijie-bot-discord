# Discord bot: สมาชิก กิจกรรม และจีจี้

บอตนี้ตอบคำสั่ง `/ล่าสุด` ด้วยรายชื่อสมาชิกที่ยังอยู่ในเซิร์ฟเวอร์และเข้าร่วมล่าสุด 10 คน พร้อมเวลาเข้าร่วม บอตไม่นับบอตและสมาชิกที่ออกจากเซิร์ฟเวอร์แล้ว

บอตบันทึกสมาชิกที่เป็นคนและออกจากเซิร์ฟเวอร์ขณะออนไลน์โดยอัตโนมัติ ใช้ `/ออกล่าสุด` ดูประวัติสูงสุด 10 รายการ พร้อมชื่อ, User ID และเวลาที่บอตรับเหตุการณ์ โดยไม่แท็กสมาชิกหรือแสดงลิงก์

ใช้ `/กิจกรรม` ตรวจข้อความย้อนหลังที่ยังอยู่, Audit Log เมื่อผู้เรียกมีสิทธิ์ และกิจกรรมที่บอตเริ่มบันทึกขณะออนไลน์ ข้อมูลกิจกรรมที่บันทึกเก็บ 30 วันและไม่เก็บเนื้อหาข้อความ

ผู้มีสิทธิ์ Manage Server ตั้งค่าห้องและข้อความต้อนรับผ่าน `/ต้อนรับ` ได้ เมื่อสมาชิกที่เป็นคนเข้าร่วมเซิร์ฟเวอร์ บอตจะส่งข้อความในห้องที่เลือก โดยแทน `{member}` ด้วยการกล่าวถึงสมาชิกใหม่

จีจี้สนทนาภาษาไทยผ่าน Google Gemini ในห้องข้อความที่ผู้ดูแลอนุญาตและเปิดไว้ คุยเรื่องทั่วไปและความบันเทิงได้ รวมดูดวงเพื่อความสนุก เรียกด้วยชื่อ `จีจี้` ที่ต้นข้อความ, mention บอต หรือ reply ข้อความบอต เลือกค้นเว็บด้วย Google Search เมื่อขอค้นหาหรือถามข้อมูลล่าสุด พร้อมลิงก์อ้างอิงและลิงก์ค้นหาต่อ เก็บความจำเฉพาะคู่ที่ไม่ใช้เครื่องมือแยกห้อง/สมาชิกสูงสุด 10 คู่และหมดอายุหลังไม่มีคู่ใหม่ 30 นาที

## คำสั่งและฟีเจอร์ปัจจุบัน

| คำสั่งใน Discord | ทำอะไร | ใครใช้ได้ |
| --- | --- | --- |
| `/ล่าสุด` | แสดงสมาชิกปัจจุบันที่เป็นคน สูงสุด 10 คน เรียงตามเวลาเข้าร่วมจากใหม่ไปเก่า พร้อมเวลาเข้าร่วม ไม่มีตัวเลือกเพิ่มเติม | สมาชิกที่ Discord อนุญาตให้ใช้คำสั่งในช่องนั้น โค้ดยังไม่ได้จำกัดเฉพาะแอดมินหรือ role ใด |
| `/ออกล่าสุด` | แสดงประวัติการออกที่บอตบันทึกได้ สูงสุด 10 รายการจากใหม่ไปเก่า พร้อมชื่อ, User ID และเวลาที่รับเหตุการณ์ ไม่มีตัวเลือกเพิ่มเติม ถ้ายังไม่มีข้อมูลจะแจ้งว่าไม่มีประวัติ | สมาชิกที่ Discord อนุญาตให้ใช้คำสั่งในช่องนั้น ไม่จำกัดเฉพาะแอดมินหรือ role |
| `/กิจกรรม สมาชิก:<สมาชิก> [ช่วงวัน:<1–30>]` | แสดงกิจกรรมล่าสุดไม่เกิน 20 รายการ เรียงใหม่ไปเก่า พร้อมเวลา ประเภท ช่องหรือลิงก์ และสถานะของแต่ละแหล่ง ค่าเริ่มต้น 7 วัน ตอบแบบเห็นเฉพาะผู้เรียก | สมาชิกที่ Discord อนุญาตให้ใช้คำสั่งในช่องนั้น ไม่จำกัด role; ผลข้อความจำกัดตามสิทธิ์ช่องของผู้เรียก และส่วน Audit Log แสดงเฉพาะผู้เรียกที่มี `View Audit Log` |
| `/ต้อนรับ ตั้งค่า ห้อง:<ห้องข้อความ> [ข้อความ:<ข้อความต้อนรับ>]`, `/ต้อนรับ ดู`, `/ต้อนรับ ปิด` | เลือกห้องและข้อความ (ละข้อความไว้เพื่อใช้ค่าเริ่มต้น), ดูค่าปัจจุบัน หรือปิดการส่งข้อความตอบแบบเห็นเฉพาะผู้เรียก ไม่มีข้อมูลย้อนหลังส่งให้สมาชิกเก่า | ผู้เรียกต้องมี `Manage Server`; บอตต้องมี `View Channel` และ `Send Messages` ในห้องต้อนรับ |
| `/จีจี้ เพิ่ม ห้อง:<ห้องข้อความ>` | ต้องเลือกห้องข้อความปกติ (`GuildText`) เพิ่มซ้ำได้โดยไม่เพิ่ม ID ซ้ำ ไม่เปลี่ยนสถานะเปิด/ปิด ตอบสถานะและจำนวนห้อง | ผู้มี `Manage Server` ปัจจุบัน; ผู้เรียกต้องดูห้องได้ และบอตต้องดูห้องและส่งข้อความได้ |
| `/จีจี้ ลบ [ห้อง:<ห้องข้อความ>] [รหัสห้อง:<Channel ID>]` | ต้องระบุอย่างใดอย่างหนึ่ง: ห้องข้อความปกติ (`GuildText`) ในเซิร์ฟเวอร์นี้ หรือรหัสห้องตัวเลข 17–20 หลักสำหรับห้องที่เลือกไม่ได้ ลบห้องและความจำทุกคนในห้องนั้น ซ้ำได้ ตอบสถานะและจำนวนห้อง โดยไม่แสดงชื่อหรือ ID | ผู้มี `Manage Server` ปัจจุบัน; ไม่ต้องมีสิทธิ์ดู/ส่งข้อความของผู้เรียกหรือบอตในห้องนั้น รวมถึงห้องที่ลบแล้ว |
| `/จีจี้ ดู` | ไม่มีตัวเลือก แสดงสถานะและรายชื่อห้องที่ผู้เรียกกับบอตดูได้ ห้องที่ซ่อน/ไม่พร้อมใช้แสดงเพียงจำนวน ไม่มีชื่อหรือ ID; รายชื่อยาวถูกจำกัดตามขนาดคำตอบ Discord | ผู้มี `Manage Server` ปัจจุบัน |
| `/จีจี้ เปิด` | ไม่มีตัวเลือก เปิดเมื่อมี Gemini key และห้องที่ผู้เรียกดูได้พร้อมสิทธิ์ดู/ส่งข้อความของบอตอย่างน้อยหนึ่งห้อง มิฉะนั้นแจ้งขั้นตอนตั้งค่า | ผู้มี `Manage Server` ปัจจุบัน |
| `/จีจี้ ปิด` | ไม่มีตัวเลือก ปิด คงรายชื่อห้อง และล้างความจำทั้งหมด | ผู้มี `Manage Server` ปัจจุบัน |
| `จีจี้ ช่วยค้นข่าวล่าสุดเรื่อง AI` หรือ `จีจี้ อากาศกรุงเทพวันนี้เป็นอย่างไร` | ข้อความแชท ไม่มี Slash command/ตัวเลือกใหม่; Gemini เลือกเรียก `search_google({query})` เพื่อค้นเว็บสาธารณะแล้วตอบพร้อมแหล่งอ้างอิงและลิงก์ค้นหาต่อจาก Google หากค้นไม่สำเร็จตอบข้อความ API failure เดิม ไม่เก็บคู่นี้ลงความจำ | สมาชิกที่ดูห้อง `GuildText` ที่เปิดและอนุญาตได้; บอตต้องดูห้องและส่งข้อความได้ |
| `/ลืม` | ไม่มีตัวเลือก ล้างเฉพาะความจำของผู้เรียกในห้องที่ใช้คำสั่ง ซ้ำได้และใช้ขณะจีจี้ปิดได้ | สมาชิกที่ Discord อนุญาตให้ใช้ Slash command ไม่ต้องมี `Manage Server` |

คำสั่งลงทะเบียนเฉพาะเซิร์ฟเวอร์ที่ระบุใน `DISCORD_GUILD_ID` คำตอบของ `/กิจกรรม` เห็นเฉพาะผู้เรียก คำสั่ง `/ต้อนรับ`, `/จีจี้` และ `/ลืม` เห็นเฉพาะผู้เรียก ส่วน `/ล่าสุด`, `/ออกล่าสุด` และคำตอบสนทนาจีจี้ตอบสาธารณะในช่องแชท หากสมาชิกที่มีข้อมูลเวลาเข้าร่วมมีน้อยกว่า 10 คน `/ล่าสุด` จะแสดงเท่าที่มี

| คำสั่งบนเครื่อง | หน้าที่ |
| --- | --- |
| `npm install` | ติดตั้งแพ็กเกจที่บอตใช้ |
| `npm run register` | สร้างหรืออัปเดตคำสั่ง `/ล่าสุด`, `/ออกล่าสุด`, `/กิจกรรม`, `/ต้อนรับ`, `/จีจี้` และ `/ลืม` ในเซิร์ฟเวอร์ที่กำหนด โดยคงคำสั่งอื่นไว้ |
| `npm start` | เปิดบอต ต้องเปิดโปรเซสค้างไว้เพื่อรับคำสั่งและบันทึกกิจกรรมใหม่ |

บอตยังไม่มีฟีเจอร์ตรวจลิงก์เชิญหรือแหล่งที่สมาชิกใช้เข้าร่วม ส่วนข้อความต้อนรับและประวัติกิจกรรมเริ่มทำงานเมื่อบอตออนไลน์ จึงไม่มีข้อมูลเหตุการณ์เข้าร่วมย้อนหลัง

## Permissions และ Intents ปัจจุบัน

ตารางนี้แสดงสิทธิ์ที่โค้ดปัจจุบันต้องใช้ การตั้งค่าใน Developer Portal และสิทธิ์จริงในเซิร์ฟเวอร์ต้องตรวจจากบัญชี Discord ของคุณ รวมถึงสิทธิ์ที่กำหนดเฉพาะแต่ละช่อง

| Permission | ใครต้องมี | ใช้ทำอะไร |
| --- | --- | --- |
| View Channels | บอต; ผู้ตั้งค่าต้อนรับ ผู้เพิ่มห้องจีจี้ และผู้คุยจีจี้ต้องมีในห้องนั้น (ลบห้องจีจี้ไม่ต้องมี) | เข้าถึงช่องคำสั่ง ห้องต้อนรับ และห้องสนทนาจีจี้; ตรวจสิทธิ์ปัจจุบันและกำหนด override รายช่องได้ |
| Send Messages | บอต | ส่งคำตอบในช่องแชท ข้อความต้อนรับ และสนทนาจีจี้; กำหนด override รายช่องได้ |
| Embed Links | บอต | แสดงผลคำสั่งเป็น embed |
| Read Message History | บอตและผู้เรียกในช่องที่ค้นย้อนหลัง; สำหรับ reply จีจี้ fallback เฉพาะบอต | ให้บอตอ่านรายการข้อความในช่องที่เข้าถึงได้ และอ่าน author ของข้อความอ้างอิงหนึ่งข้อความสำหรับ reply จีจี้เมื่อ Discord ไม่ส่ง author มา; การบันทึก event ใหม่ยังทำงานได้โดยไม่มีสิทธิ์นี้ |
| Manage Server | ผู้เรียก `/ต้อนรับ` และ `/จีจี้`; บอตไม่ต้องมี | จำกัดคำสั่งตั้งค่าให้ผู้ดูแลเซิร์ฟเวอร์ ทั้งค่าเริ่มต้นของ Slash command และตรวจสอบตอนเรียกใช้; `/ลืม` และการสนทนาไม่ต้องมี |
| View Audit Log | บอตและผู้เรียกที่ต้องการดูส่วน Audit Log | ใช้ดูรายการ kick/ban และการจัดการเซิร์ฟเวอร์; ถ้าขาดสิทธิ์จะข้ามแหล่งนี้ |
| Administrator | ไม่มีใครต้องใช้ | ให้เฉพาะสิทธิ์ที่จำเป็นตามตาราง ไม่ต้องใช้ role Administrator |

| OAuth2 Scope | ต้องเลือกหรือไม่ | ใช้ทำอะไร |
| --- | --- | --- |
| `bot` | เลือก | เพิ่มบัญชีบอตเข้าเซิร์ฟเวอร์ |
| `applications.commands` | เลือก | เปิดใช้คำสั่ง Slash |

| Gateway Intent | การตั้งค่า | ใช้ทำอะไร |
| --- | --- | --- |
| `Guilds` | เปิดในโค้ด ไม่ใช่สวิตช์ Privileged Intent | รับข้อมูลเซิร์ฟเวอร์ที่บอตอยู่ |
| `GuildMembers` / Server Members Intent | เปิดในโค้ด และเปิดสวิตช์ใน Developer Portal | ดึงรายชื่อสมาชิกทั้งหมดเพื่อเรียงเวลาเข้าร่วม และรับเหตุการณ์สมาชิกเข้า/ออกเพื่อบันทึกประวัติและส่งข้อความต้อนรับ |
| `GuildMessages` | เปิดในโค้ด ไม่ใช่สวิตช์ Privileged Intent | รับ event ส่งข้อความเพื่อเก็บ metadata กิจกรรมและส่งต่อข้อความที่เรียกจีจี้; ไฟล์กิจกรรมไม่เก็บเนื้อหา |
| `GuildVoiceStates` | เปิดในโค้ด ไม่ใช่สวิตช์ Privileged Intent | รับ event เข้า/ออก/ย้ายห้องเสียง |
| Presence Intent | ปิด | ฟีเจอร์ปัจจุบันไม่อ่านสถานะออนไลน์ |
| `MessageContent` / Message Content Intent | เปิดในโค้ด และเปิดสวิตช์ใน Developer Portal | อ่านเนื้อหาข้อความที่เรียกจีจี้ด้วยชื่อ/mention/reply เพื่อส่งคำถามให้ Gemini; ไม่เพิ่มเนื้อหาในไฟล์กิจกรรม |

## ต้องเตรียมอะไรบ้าง

1. **Bot Token** — ใน [Discord Developer Portal](https://discord.com/developers/applications) เปิดแอปของบอต ไปที่ **Bot** แล้วกด **Reset Token** หรือ **View Token** จากนั้นคัดลอกเก็บไว้เป็นความลับ
2. **Application ID (Client ID)** — อยู่ที่หน้า **General Information** ของแอป
3. **Server ID (Guild ID)** — เปิด Discord **User Settings → Advanced → Developer Mode** แล้วคลิกขวาที่ชื่อเซิร์ฟเวอร์ เลือก **Copy Server ID**

## ตั้งค่าบอตใน Discord

1. ใน Developer Portal ไปที่ **Bot → Privileged Gateway Intents** แล้วเปิด **Server Members Intent** และ **Message Content Intent** จากนั้นบันทึกการเปลี่ยนแปลง
2. ไปที่ **OAuth2 → URL Generator** เลือก scopes `bot` และ `applications.commands`
3. เลือกสิทธิ์บอต `View Channels`, `Send Messages`, `Embed Links` และ `Read Message History` เปิดลิงก์ที่สร้าง แล้วเชิญบอตเข้าเซิร์ฟเวอร์ หลังตั้งค่าห้องต้อนรับ ให้ตรวจ override ของห้องนั้นว่าบอตมี `View Channel` และ `Send Messages`
4. ถ้าต้องการดูส่วน Audit Log ของ `/กิจกรรม` ให้เพิ่ม `View Audit Log` ให้บอต และให้ผู้เรียกมีสิทธิ์นี้ด้วย สิทธิ์นี้ไม่จำเป็นต่อการใช้แหล่งข้อความหรือกิจกรรมที่บันทึกใหม่

จีจี้ต้องเปิด **Message Content Intent** เพราะอ่านข้อความธรรมดาที่ใช้เรียกบอต โค้ดขอ intent นี้แม้ยังไม่ตั้ง Gemini key; บอตที่ติดตั้งแล้วต้องเปิดสวิตช์ใน **Developer Portal → Bot → Privileged Gateway Intents** และรีสตาร์ต ไม่ต้องเพิ่ม OAuth2 scope, `Administrator`, `Manage Server` ให้บอต หรือ `View Audit Log` เพื่อคุยกับจีจี้ สิทธิ์เดิมให้ตรวจที่ **Server Settings → Roles** และ **Edit Channel → Permissions** ของห้องสนทนา

## ติดตั้งและเปิดบอต

ใช้ Node.js 20.6.0 ขึ้นไป จากโฟลเดอร์โปรเจกต์รัน:

```sh
npm install
cp .env.example .env
```

เปิด `.env` แล้วกรอกค่าจาก Discord:

```dotenv
DISCORD_TOKEN=วาง_Bot_Token_ที่นี่
DISCORD_CLIENT_ID=วาง_Application_ID_ที่นี่
DISCORD_GUILD_ID=วาง_Server_ID_ที่นี่
```

ลงทะเบียนคำสั่งในเซิร์ฟเวอร์ แล้วเปิดบอต:

```sh
npm run register
npm start
```

ต้องเปิดโปรเซส `npm start` ค้างไว้เพื่อให้บอตออนไลน์ ตอบคำสั่ง และเก็บกิจกรรมใหม่ ถ้าเปลี่ยนค่า `.env` ให้หยุดแล้วเปิดบอตใหม่

### เปิดใช้จีจี้หรืออัปเดตบอตที่ติดตั้งแล้ว

1. กรอก `GEMINI_API_KEY` ใน `.env` จาก [Google AI Studio](https://aistudio.google.com/apikey) และเลือก `GEMINI_MODEL` ที่บัญชีใช้ได้ (เว้นว่างเพื่อใช้ `gemini-2.5-flash`) ดูเงื่อนไขข้อมูลและ quota ในหัวข้อ Gemini ด้านล่าง
2. ไปที่ **Discord Developer Portal → แอปของบอต → Bot → Privileged Gateway Intents** เปิด **Message Content Intent** พร้อม **Server Members Intent** แล้วบันทึก
3. หยุดโปรเซสบอตเดิมก่อนอัปเดต/เริ่มใหม่ ใช้หนึ่งโปรเซสต่อชุดข้อมูล และสำรอง `data/` หากย้ายเครื่อง
4. รัน `npm run register` เพื่อลงทะเบียน `/จีจี้` กับ `/ลืม` และอัปเดตคำสั่งเดิม รวมตัวเลือก `รหัสห้อง` ของ `/จีจี้ ลบ` โดย PATCH/POST ทีละคำสั่งและคงคำสั่งอื่นไว้
5. รัน `npm start` และเปิดโปรเซสค้างไว้
6. ผู้มี `Manage Server` ใช้ `/จีจี้ เพิ่ม ห้อง:#chat` โดยตนเองกับบอตต้องดูห้องได้และบอตส่งข้อความได้ เพิ่มหลายห้องได้ แต่การเพิ่มไม่เปิดจีจี้เอง
7. ใช้ `/จีจี้ เปิด` แล้วลอง `จีจี้สวัสดี` ในห้องนั้น ใช้ `/จีจี้ ดู` ตรวจสถานะ; หากไม่มี key หรือห้องพร้อมใช้งาน คำสั่งจะแจ้งสิ่งที่ต้องตั้งค่า

หากเปลี่ยนเฉพาะ key/model ให้หยุดแล้วเปิดบอตใหม่ ไม่ต้องลงทะเบียนคำสั่งซ้ำ หากไม่มี Gemini key คำสั่งเดิมยังทำงานได้ แต่ `/จีจี้ เปิด` จะปฏิเสธ ยังต้องเปิด Message Content Intent ตามโค้ดปัจจุบัน

## ใช้งาน

พิมพ์ `/ล่าสุด` ในช่องแชทของเซิร์ฟเวอร์ บอตจะแสดงสมาชิกเรียงจากคนที่เพิ่งเข้าร่วมที่สุด เวลาในรายการจะแสดงตามเขตเวลาของผู้ดูแต่ละคน

ตัวอย่าง: พิมพ์ `/ออกล่าสุด` บอตจะตอบเช่น `1. Somchai (ID: 123456789012345678) — [เวลาออก]` ถ้ามีข้อมูล 3 รายการจะแสดงเพียง 3 รายการ เวลาแสดงตามเขตเวลาของผู้ดู

ตัวอย่าง: พิมพ์ `/กิจกรรม สมาชิก:@Somchai ช่วงวัน:7` เพื่อดูข้อมูลของ Somchai ย้อนหลัง 7 วัน ผลลัพธ์แสดงสูงสุด 20 รายการ เช่น เวลาส่งข้อความและลิงก์ข้อความ, เข้า/ออก/ย้ายห้องเสียง และรายการ Audit Log ที่เกี่ยวข้อง ผู้เรียกคนอื่นจะไม่เห็นคำตอบนี้

ตั้งค่าข้อความต้อนรับได้ด้วย `/ต้อนรับ ตั้งค่า ห้อง:#welcome` หรือระบุข้อความ เช่น `/ต้อนรับ ตั้งค่า ห้อง:#welcome ข้อความ:ยินดีต้อนรับ {member} 🎉` ใช้ `/ต้อนรับ ดู` เพื่อตรวจค่าปัจจุบัน และ `/ต้อนรับ ปิด` เพื่อหยุดส่งข้อความ

## ข้อความต้อนรับและข้อจำกัด

- ผู้เรียก `/ต้อนรับ` ต้องมี `Manage Server` คำสั่งตรวจสิทธิ์นี้ทั้งตอนแสดงใน Discord และตอนทำงาน บัญชีบอตไม่ต้องมี `Manage Server`
- `/ต้อนรับ ตั้งค่า ห้อง:#welcome [ข้อความ:<template>]` ตั้งค่าห้องข้อความในเซิร์ฟเวอร์ที่กำหนด เมื่อละข้อความไว้จะใช้ `ยินดีต้อนรับ {member} เข้าสู่เซิร์ฟเวอร์ 🎉` การตั้งค่าใหม่แทนค่าก่อนหน้า `/ต้อนรับ ดู` แสดงสถานะ ห้อง และข้อความปัจจุบัน; `/ต้อนรับ ปิด` ปิดการส่งและล้างห้องกับข้อความ ทุกคำสั่งตอบแบบเห็นเฉพาะผู้เรียก
- ระบุ `{member}` เพื่อกล่าวถึงสมาชิกใหม่ ใช้ซ้ำได้และระบบแทนทุกตำแหน่ง ข้อความที่ไม่มีตัวแปรนี้ก็ใช้ได้ โดยไม่กล่าวถึงใคร ระบบไม่ส่ง ping ให้ role, `@everyone` หรือ `@here` จำกัด template ที่ 1,000 หน่วย UTF-16 และข้อความหลังแทนตัวแปรไม่เกิน 2,000 หน่วย UTF-16
- ห้องที่ตั้งค่าต้องเป็นห้องข้อความปกติ ผู้ตั้งค่าและบอตต้องดูห้องได้ และบอตต้องส่งข้อความได้ หากผู้ตั้งค่าไม่มีสิทธิ์ดูห้องนั้น `/ต้อนรับ ดู` จะซ่อนชื่อห้องและข้อความไว้
- ส่งข้อความเมื่อบัญชีคนเข้าเซิร์ฟเวอร์ที่ตั้งค่าและบอตออนไลน์อยู่ บัญชีบอตจะไม่ได้รับข้อความ การกลับเข้าใหม่ถือเป็น join ใหม่ ไม่มีข้อความย้อนหลังสำหรับสมาชิกเดิม ช่วงออฟไลน์ หรือเหตุการณ์ที่พลาดไป และบอตไม่ระบุลิงก์เชิญที่สมาชิกใช้
- บันทึกค่าปัจจุบันใน `data/welcome.json` รูปแบบ version 1 มี `guildId`, `channelId` และ `template`; ค่าปิดใช้ห้องและข้อความเป็น `null` หากไม่มีไฟล์ให้ถือว่าปิด บอตเขียนไฟล์ชั่วคราวแล้วเปลี่ยนชื่อแบบ atomic เพื่อเก็บค่าถาวรหลังรีสตาร์ต ไฟล์อยู่ใต้ `data/` ซึ่งไม่ส่งเข้า Git ไม่ต้องเพิ่มค่าใน `.env` หรือเปลี่ยน schema ประวัติกิจกรรม
- หากไฟล์เสียหรือเป็นของอีกเซิร์ฟเวอร์ บอตจะไม่เริ่มทำงาน ให้สำรอง `data/` แล้วย้ายไฟล์เดิมออกก่อนเปิดบอตใหม่ ใช้บอตหนึ่งโปรเซสต่อไฟล์ข้อมูล และสำรอง `data/` เมื่อต้องย้ายเครื่อง
- หากส่งข้อความไม่สำเร็จ บอตเก็บการตั้งค่าไว้และยังพยายามบันทึก join ใน `/กิจกรรม` แยกต่างหาก บอตไม่ลองส่งซ้ำอัตโนมัติและไม่มีคิวส่งย้อนหลัง เหตุการณ์ที่พลาดระหว่างออฟไลน์หรือโปรเซสหยุดอาจไม่มีข้อความต้อนรับ

เมื่อติดตั้งบอตไว้แล้ว ให้สร้างหรือเลือกห้องข้อความและให้บอตมี `View Channel` กับ `Send Messages` ในห้องนั้น ตรวจว่าเปิด Server Members Intent ใน Developer Portal แล้วหยุดโปรเซสเดิม รัน `npm run register` และ `npm start` จากนั้นใช้ `/ต้อนรับ ตั้งค่า ห้อง:#welcome` โดยผู้ตั้งค่าต้องมี `Manage Server` การตั้งค่าห้องและข้อความเปลี่ยนได้ภายหลังโดยไม่ต้องแก้ `.env` หรือรันคำสั่งลงทะเบียนซ้ำ

## ประวัติกิจกรรมและข้อจำกัด

- ค้นข้อความย้อนหลังที่ยังอยู่ในช่องข้อความ/ประกาศและ public thread ที่ยัง active โดยทั้งบอตและผู้เรียกต้องมี `View Channel` และ `Read Message History` ในช่องนั้น private thread และ archived thread ไม่ถูกค้น
- สแกนไม่เกิน 1,000 ข้อความต่อช่อง, 10,000 ข้อความรวม และ 60 วินาทีต่อคำสั่ง ผลแสดงไม่เกิน 20 รายการ ระบบบอกเมื่อข้อมูลบางส่วนค้นไม่ได้หรือถึงขีดจำกัด; การไม่พบรายการไม่ได้ยืนยันว่าไม่มี activity
- ส่วน Audit Log ต้องมี `View Audit Log` ทั้งจากผู้เรียกและบอต ค้นรายการที่ผู้ใช้เป็นผู้กระทำหรือเป็นเป้าหมาย แยกสองบทบาทให้เห็น ไม่แสดง reason หรือรายละเอียดการเปลี่ยนแปลง Discord เก็บ Audit Log 45 วัน ส่วนคำสั่งนี้ให้เลือกได้สูงสุด 30 วัน รายการที่อ้างถึงช่องถูกซ่อนเมื่อผู้เรียกไม่มีสิทธิ์ดูช่องนั้น
- เมื่อบอตออนไลน์และเชื่อมต่อเซิร์ฟเวอร์ที่ตั้งค่า จะเก็บการส่งข้อความ, เข้า/ออก/ย้ายห้องเสียง และเข้า/ออกเซิร์ฟเวอร์ของบัญชีคน ไม่เก็บเนื้อหา, reaction, สถานะออนไลน์ หรือการแก้ไข/ลบข้อความ การออกจากเซิร์ฟเวอร์อาจเป็นออกเอง ถูกเตะ หรือถูกแบน จึงไม่ยืนยันเหตุผล
- ข้อมูลย้อนหลังของข้อความมีเฉพาะข้อความที่ยังอยู่และช่องที่เข้าถึงได้ ข้อมูล event ใหม่เริ่มจากตอนเปิดบอต ไม่มีข้อมูลย้อนหลังช่วงที่บอตออฟไลน์หรือก่อนติดตั้ง และไม่สร้าง event เข้า voice ย้อนหลังเมื่อบอตเริ่มทำงาน
- ระบบเก็บเฉพาะเวลา, ประเภท event, User ID และ Channel/Message IDs ที่จำเป็นต่อการสร้างลิงก์ ไม่เก็บเนื้อหาข้อความ; event ที่ระบุช่องจะแสดงเมื่อผู้เรียกและบอตยังมีสิทธิ์เข้าถึงช่องนั้น ลิงก์ข้อความอาจใช้ไม่ได้เมื่อข้อความถูกลบ
- เก็บไฟล์ JSON รายวันตามวัน UTC ใน `data/activity/`; แต่ละไฟล์มี `version: 1`, `guildId` และ `records` ซึ่งมี `type`, `userId`, `at` (Unix milliseconds) และ Channel/Message IDs เท่าที่จำเป็น ส่วน `manifest.json` มี version, guild ID และวันเริ่มเก็บ ลบ event ที่เก่ากว่า 30 วันเมื่อเริ่มระบบและทุกชั่วโมง ไม่ต้องเพิ่มค่า `.env` ใช้พื้นที่เก็บที่เขียนได้และคงอยู่หลังรีสตาร์ต สำรองโฟลเดอร์ `data/` เมื่อต้องย้ายเครื่อง
- ใช้บอตหนึ่งโปรเซสต่อชุดไฟล์ หากไฟล์เสียหรือเป็นของอีกเซิร์ฟเวอร์ บอตจะไม่เริ่มทำงาน ให้สำรองและย้ายไฟล์เดิมออกก่อนเริ่มระบบใหม่ ข้อมูลประวัติกิจกรรมแยกจากไฟล์ `data/departures.json` และไม่ย้ายประวัติการออกเดิมมาเป็นกิจกรรม
- หากอ่านหรือเขียนไฟล์ไม่ได้ ระบบระบุสถานะแหล่งข้อมูลที่ผิดพลาด; event ที่ยังเขียนไม่สำเร็จอาจหายหากโปรเซสหยุดก่อนบันทึกสำเร็จ

อ้างอิง: [Discord Get Channel Messages](https://docs.discord.com/developers/resources/message#get-channel-messages), [Gateway Events](https://docs.discord.com/developers/events/gateway-events) และ [Audit Log](https://docs.discord.com/developers/resources/audit-log)

## ประวัติการออกและข้อจำกัด

- เริ่มเก็บทันทีเมื่อบอตเชื่อมต่อ Discord และเปิด Server Members Intent ไม่ต้องพิมพ์คำสั่งก่อน เก็บเฉพาะเซิร์ฟเวอร์ใน `DISCORD_GUILD_ID` และไม่นับบัญชีบอต
- ไม่สามารถดึงประวัติคนที่กดออกเองก่อนเริ่มระบบนี้หรือระหว่างบอตออฟไลน์ย้อนหลังจาก Audit Log ได้ บอตนี้ไม่อ่านประวัติ kick/ban จาก Audit Log
- เหตุการณ์ `GuildMemberRemove` รวมออกเอง ถูกเตะ และถูกแบน รายการจึงไม่ยืนยันเหตุผล เวลาเป็นเวลาที่บอตรับเหตุการณ์ ไม่ใช่เวลาย้อนหลังที่ Discord ยืนยัน
- เก็บ 10 เหตุการณ์ล่าสุด ถ้าคนเดิมกลับเข้าแล้วออกอีก จะมีรายการใหม่ของคนนั้น รายชื่อเป็นชื่อที่ทราบตอนออกและอาจเปลี่ยนภายหลัง
- เก็บใน `data/departures.json` ภายใต้โฟลเดอร์โปรเจกต์ รูปแบบ JSON version 1 มี `guildId` และ `records` แต่ละรายการมี `userId`, `name`, `leftAt` (Unix milliseconds) ไม่ต้องเพิ่มค่า `.env` หรือสิทธิ์ใหม่
- สร้างไฟล์เมื่อมีเหตุการณ์แรก เขียนตามลำดับผ่านไฟล์ชั่วคราวแล้วเปลี่ยนชื่อ อ่านประวัติเดิมเมื่อรีสตาร์ต เก็บเฉพาะล่าสุด 10 รายการและไม่ส่งไฟล์นี้เข้า Git
- ต้องใช้พื้นที่เก็บไฟล์ที่เขียนได้และคงอยู่หลังรีสตาร์ต สำรองโฟลเดอร์ `data/` เมื่อต้องย้ายเครื่อง รันเพียงหนึ่งโปรเซสต่อไฟล์ข้อมูล หากลบไฟล์ประวัติจะหาย หากไฟล์เสียหรือเป็นของอีกเซิร์ฟเวอร์บอตจะไม่เริ่มทำงาน ให้สำรองและย้ายไฟล์เดิมออกก่อนเริ่มใหม่
- ถ้าการเขียนล้มเหลว คำสั่งจะแจ้งข้อผิดพลาดจนกว่าจะบันทึกสำเร็จในเหตุการณ์ถัดไป ข้อมูลที่ยังเขียนไม่สำเร็จอาจหายถ้าโปรเซสหยุด

อ้างอิง: [Discord Gateway — Guild Member Remove](https://docs.discord.com/developers/events/gateway-events#guild-member-remove) และ [Audit Log](https://docs.discord.com/developers/resources/audit-log)

### อัปเดตบอตที่ติดตั้งแล้ว

1. ตรวจว่าเปิด **Server Members Intent** และ **Message Content Intent** ใน Developer Portal แล้ว โค้ดเปิด `GuildMessages`, `GuildVoiceStates` และ `MessageContent` อยู่แล้ว
2. ไปที่ **Server Settings → Roles** แล้วเพิ่ม `Read Message History` ให้ role ของบอต จากนั้นตรวจ channel overrides ให้บอตและผู้เรียกมี `View Channel` กับ `Read Message History` ในช่องที่ต้องการค้น
3. ถ้าต้องการส่วน Audit Log ให้เพิ่ม `View Audit Log` ให้ role ของบอต และให้ผู้เรียกที่ต้องการดูมีสิทธิ์นี้
4. หยุดโปรเซสบอตเดิม รัน `npm run register` เพื่อลงทะเบียนคำสั่งใหม่และอัปเดตคำสั่งเดิม โดยคงคำสั่งอื่นไว้
5. รัน `npm start` ใหม่ การเก็บกิจกรรมเริ่มเมื่อบอตเชื่อมต่อสำเร็จ; ตรวจด้วยบัญชีทดสอบการส่งข้อความ, ย้ายห้องเสียง, ออกจากเซิร์ฟเวอร์ และสิทธิ์ Audit Log

อย่าแชร์หรือส่งไฟล์ `.env` ให้ผู้อื่น เพราะมี Bot Token ที่ใช้ควบคุมบอตได้

## การเพิ่มฟีเจอร์ครั้งต่อไป

ทำตาม [AGENTS.md](AGENTS.md) และอัปเดตเอกสารพร้อมโค้ดทุกครั้ง: เพิ่มคำสั่งและตัวเลือกใหม่ในตารางคำสั่ง เพิ่ม permissions/intents/scopes ที่จำเป็น ระบุค่า `.env` ใหม่พร้อมแหล่งที่มา และอธิบายข้อจำกัดหรือขั้นตอนตั้งค่าเพิ่มเติม หากมีวิธีทำงานหรือกติกาบำรุงรักษาใหม่ ให้เติม instruction ใน `AGENTS.md` ด้วย
## ที่เก็บข้อมูลสนทนาจีจี้

`src/jiji/jiji-runtime.js` เปิด settings และ memory พร้อมตรวจความสอดคล้องก่อน login จากนั้นเชื่อม provider, การสนทนา และ Jiji command handler; `src/commands/interaction-dispatch.js` route interaction ไปยัง handler ของแต่ละฟีเจอร์ ส่วน `src/index.js` ประกอบ modules กับ Gateway events การบันทึกกิจกรรมแยกจากงานสนทนา จึงยังบันทึก metadata ของข้อความคนได้แม้ Gemini ช้าหรือล้มเหลว; บอตและ webhook ไม่เข้าแชทหรือประวัติกิจกรรม

- `src/jiji/jiji-settings.js` จัดเก็บ `data/jiji-settings.json` รูปแบบ version 1 มีเฉพาะ `{version:1,guildId,enabled,channelIds}` โดย `enabled` เป็น boolean และ `channelIds` เป็นรายการ Snowflake ID ของห้องที่ไม่ซ้ำกัน หากไม่มีไฟล์ ค่าเริ่มต้นคือปิดและไม่มีห้อง การเพิ่มห้องไม่เปลี่ยนสถานะเปิด/ปิด และการปิดคงรายชื่อห้องไว้
- `src/jiji/jiji-memory.js` จัดเก็บ `data/jiji-memory.json` รูปแบบ version 1 มีเฉพาะ `{version:1,guildId,sessions}` แต่ละ session มี `{channelId,userId,updatedAt,turns}` และแต่ละ turn มี `{user,assistant,at}` เวลาเป็นจำนวนเต็ม Unix milliseconds ที่ไม่ติดลบ เรียง turn ตามเวลาโดยเวลา turn สุดท้ายเท่ากับ `updatedAt`; ข้อความทั้งสองฝั่งต้องไม่ว่างและไม่เกิน 2,000 หน่วย UTF-16
- แยกความจำตามห้องและสมาชิก เก็บสูงสุด 10 คู่คำถาม/คำตอบที่สมบูรณ์ต่อ session และ 1,000 sessions หากเต็มให้ลบ session ที่ `updatedAt` เก่าสุดก่อน กรณีเวลาเท่ากันเรียงตาม Channel ID แล้ว User ID เพื่อให้ผลแน่นอน
- หมดอายุเมื่อไม่มีคู่ใหม่เป็นเวลา **ตั้งแต่ 1,800,000 ms (30 นาที)** ล้างรายการหมดอายุและบันทึกการล้างเมื่อเปิด store, อ่าน, เขียน หรือเรียก `prune()` การรีสตาร์ตไม่ต่ออายุความจำและไม่สร้างความจำจากประวัติ Discord runtime เรียก `prune()` ทุกนาทีและ `reconcile()` ตอนเริ่มระบบเพื่อล้างห้องที่ไม่อยู่ในรายชื่อหรือความจำทั้งหมดเมื่อปิด รวมกรณีหยุดระหว่างบันทึก settings กับการล้าง memory
- เขียนตามลำดับผ่านไฟล์ชั่วคราว mode `0600` แล้วเปลี่ยนชื่อแบบ atomic; เปลี่ยนค่าที่อ่านได้ในโปรเซสหลังบันทึกสำเร็จเท่านั้น หากเขียนหรือเปลี่ยนชื่อไม่ได้ operation จะล้มเหลวโดยค่าก่อนหน้ายังอยู่ และลบไฟล์ `jiji-memory.json.tmp` ที่อาจมีเนื้อหาบทสนทนาค้างอยู่ บอตลบไฟล์ชั่วคราวตกค้างก่อนอ่าน JSON หลักตอนเริ่มระบบและก่อนทุก operation รวมการล้าง/หมดอายุ/reconcile ที่ไม่มีรายการให้เปลี่ยน โดยไม่ใช้ไฟล์ชั่วคราวเป็นความจำที่บันทึกสำเร็จ หากลบไม่ได้ operation หรือการเริ่มระบบจะล้มเหลวให้แก้สิทธิ์พื้นที่จัดเก็บก่อนลองใหม่ คำสั่งล้างที่เข้าคิวหลัง append ซึ่งเริ่มแล้วจะล้างผล append นั้นด้วย
- เก็บเฉพาะคู่ข้อความธรรมดาที่ส่งคำตอบสำเร็จ ไม่เก็บคำตอบที่ใช้ tool, คำทักทาย, ข้อผิดพลาด, API key, raw provider response, attachment หรือข้อความของผู้อื่น `src/jiji/jiji-chat.js` บังคับกฎนี้ก่อนเรียก append; เป็นข้อยกเว้นเฉพาะไฟล์ความจำจีจี้ ส่วนไฟล์กิจกรรมยังเก็บ metadata เท่านั้น
- handler `/ลืม` ลบเฉพาะความจำในบอตของผู้เรียกในห้องนั้น ไม่ลบข้อความ Discord หรือข้อมูลที่ส่งให้ Gemini แล้ว การลบข้อความบน Discord ไม่ล้างความจำในไฟล์โดยอัตโนมัติ
- ใช้บอตหนึ่งโปรเซสต่อชุดไฟล์ เก็บ `data/` ไว้ในพื้นที่ที่เขียนได้และคงอยู่หลังรีสตาร์ต; โฟลเดอร์นี้ถูกละเว้นจาก Git และมีเนื้อหาบทสนทนา จึงควรจำกัดผู้เข้าถึง สำรอง `data/` เมื่อต้องย้ายเครื่อง โดยสำเนาสำรองอาจยังมีบทสนทนาที่ล้างในไฟล์ปัจจุบันแล้ว
- หาก JSON เสีย, version/รูปแบบไม่ตรง, session ซ้ำ หรือเป็นของอีกเซิร์ฟเวอร์ store จะไม่เปิดและไม่เขียนทับไฟล์เดิม ให้สำรองไฟล์แล้วแยกไฟล์ที่เสียออกก่อนเริ่มใหม่เพื่อเริ่มโดยไม่มีข้อมูลเดิม ไม่มี migration จากประวัติ departure/activity/welcome และสัญญา version 1 ของไฟล์เหล่านั้นไม่เปลี่ยน

### คำสั่งควบคุมจีจี้

ตัวเลือก ผลตอบกลับ และผู้ใช้แต่ละคำสั่งอยู่ในตารางคำสั่งปัจจุบันด้านบน

ทุกคำตอบเห็นเฉพาะผู้เรียกและไม่กล่าวถึงสมาชิก/role; handler รับคำสั่งก่อนทำงานช้า `/จีจี้` ตั้ง default slash permission เป็น `Manage Server` และตรวจสิทธิ์จากสมาชิกกับ roles ที่ดึงใหม่ แยกจาก `/ลืม` ที่ไม่จำกัดสิทธิ์ผู้ดูแล การคำนวณสิทธิ์ห้องใช้ห้อง สมาชิกผู้เรียก สมาชิกบอต และ roles ที่ดึงใหม่ ไม่ใช้สิทธิ์เก่าจาก interaction

ตัวอย่าง: `/จีจี้ เพิ่ม ห้อง:#chat`, `/จีจี้ เพิ่ม ห้อง:#general`, `/จีจี้ ดู`, `/จีจี้ เปิด`, `/ลืม`, `/จีจี้ ลบ ห้อง:#chat`, `/จีจี้ ลบ รหัสห้อง:123456789012345678`, `/จีจี้ ปิด` การเพิ่มหลายห้องไม่เปิดจีจี้อัตโนมัติ ตรวจ override ห้องให้ผู้ตั้งค่าและบอตมี `View Channel` และบอตมี `Send Messages` บอตไม่ต้องมี `Manage Server`, `Administrator`, `View Audit Log` หรือ OAuth2 scope ใหม่เพื่อใช้ handler เหล่านี้ ตั้งค่า Gemini ตามหัวข้อด้านล่างและเปิด Message Content Intent ตามขั้นตอนเปิดใช้จีจี้ด้านบน

`/จีจี้ ลบ` ต้องเลือก `ห้อง` หรือกรอก `รหัสห้อง` อย่างใดอย่างหนึ่งเท่านั้น ตัวเลือกห้องรับเฉพาะห้องข้อความปกติในเซิร์ฟเวอร์นี้ ส่วนรหัสห้องรับตัวเลข 17–20 หลักและไม่ต้องให้ Discord คืน object ของห้อง จึงลบห้องที่ซ่อนหรือถูกลบไปแล้วออกจากรายชื่อได้ ผู้เรียกยังต้องมี `Manage Server` ปัจจุบัน ทั้งสองแบบไม่ตรวจสิทธิ์ดู/ส่งข้อความของห้องและไม่แสดง ID ในคำตอบ สำหรับห้องที่ยังอยู่ เปิด **User Settings → Advanced → Developer Mode** แล้วคลิกขวาห้องเลือก **Copy Channel ID**; สำหรับห้องที่ลบแล้ว ผู้ดูแลเครื่องบอตดู ID ที่เคยบันทึกในรายการ `channelIds` ของไฟล์ท้องถิ่น `data/jiji-settings.json` แล้วใช้ `/จีจี้ ลบ รหัสห้อง:<ID>` ไม่ต้องแก้ JSON เอง `/จีจี้ ดู` จะไม่เปิดเผย ID ของห้องที่ซ่อน หลังอัปเดตตัวเลือกคำสั่งนี้ให้หยุดบอต รัน `npm run register` แล้ว `npm start` อีกครั้ง

`/จีจี้ ดู` และ `/จีจี้ เปิด` ข้ามห้องที่ลบหรือเข้าถึงไม่ได้เมื่อการดึงห้องคืน Unknown Channel (`10003`), Missing Access (`50001`) หรือ Missing Permissions (`50013`); `/ดู` นับเป็นห้องซ่อนโดยไม่แสดงชื่อ/ID และ `/เปิด` ยังเปิดได้เมื่อมีห้องอื่นที่พร้อมอย่างน้อยหนึ่งห้องพร้อม Gemini key ข้อผิดพลาดเครือข่ายหรือดึงสมาชิก/roles ไม่สำเร็จยังตอบข้อผิดพลาดตรวจสิทธิ์ ไม่รายงานเป็นเพียงห้องซ่อน

`src/jiji/jiji-access.js` ตรวจสิทธิ์ห้องจาก Discord ใหม่; `src/jiji/jiji-command.js` เป็นเจ้าของ command data และการตอบ interaction โดยเรียก store ของแต่ละไฟล์ การล้าง/ปิด/ลบห้องทำให้คำถามที่ยังรออยู่หมดสิทธิ์ส่งคำตอบหรือบันทึกความจำก่อนเริ่มเขียนไฟล์ runtime ส่ง callback `invalidate` ที่ทำงานทันทีและยกเลิกงานที่รอเมื่อปิดโปรเซส การปิดหรือลบห้องบันทึก settings ให้สำเร็จก่อนล้าง memory; หากล้างล้มเหลวต้องแจ้งข้อผิดพลาดและ runtime เรียก `reconcile()` ตอนเริ่มระบบ เพื่อซ่อมความจำที่เหลือจากงานที่ขาดตอน คำสั่งล้มเหลวอาจยกเลิกคำถามที่กำลังรอแล้ว แต่จะไม่อ้างว่าล้างความจำสำเร็จ

### เครื่องมืออ่านข้อมูลของจีจี้

`src/jiji/jiji-tools.js` ประกาศเครื่องมือ Discord สามรายการและ `search_google` ต่อไปนี้สำหรับคำถามในแชท ไม่ใช่ Slash command เพิ่มเติม

| เครื่องมือภายใน | ข้อมูลและข้อจำกัด |
| --- | --- |
| `get_latest_members({})` | สมาชิกปัจจุบันที่เป็นคนสูงสุด 10 คน เรียงเหมือน `/ล่าสุด` พร้อม `userId`, `name`, `joinedAt` (Unix milliseconds) ดึงสมาชิกทั้งหมดจาก Discord ใหม่ หากดึงล้มเหลวจะคืนข้อผิดพลาด ไม่ใช้ cache บางส่วนแทนผลครบ |
| `get_recent_departures({})` | อ่านข้อมูลเดิมของ `/ออกล่าสุด` สูงสุด 10 รายการ พร้อม `userId`, `name`, `leftAt` (Unix milliseconds) ระบุ `coverage: recorded_while_online` และ `reason: unknown` แม้ไม่มีรายการ ไม่ยืนยันว่าออกเอง ไม่ครอบคลุมช่วงที่บอตออฟไลน์ และความล้มเหลวของไฟล์ไม่ใช่ประวัติว่าง |
| `search_google({query})` | คำค้นข้อความไม่ว่าง ไม่เกิน 500 หน่วย UTF-16 รับเฉพาะ `query`; ค้นเว็บสาธารณะผ่าน Gemini Google Search ด้วย key/model เดิม ตรวจสิทธิ์ก่อนค้นและก่อนส่งคำตอบ ไม่อ่านเว็บเอง ไม่คลิกหรือดาวน์โหลดไฟล์ |
| `activity_help({})` | คืนข้อความ `ใช้ /กิจกรรม สมาชิก:@สมาชิก [ช่วงวัน:1–30] เพื่อดูผลแบบเห็นเฉพาะคุณนะ 🔎` เท่านั้น ไม่อ่านประวัติกิจกรรมหรือ Audit Log |

เครื่องมือ Discord สามรายการรับเฉพาะ object ว่าง ส่วน `search_google` รับเฉพาะ `{query}` เลือกเซิร์ฟเวอร์ ห้อง หรือสมาชิกผ่าน arguments ไม่ได้ ตรวจเซิร์ฟเวอร์และ callback ตรวจสิทธิ์ปัจจุบันทุกครั้งก่อนอ่านข้อมูล ผลที่กลับมาหลังยกเลิกจะถูกละทิ้ง `src/jiji/jiji-chat.js` ส่งบริบทผู้เรียก/ห้องและ callback นี้ และแปลง `member_fetch_failed` / `departure_read_failed` เป็นข้อความไทยเรื่องดึงสมาชิกหรือไฟล์ข้อมูลแบบเดียวกับคำสั่งเดิม ไม่แสดงรายละเอียดข้อผิดพลาดจาก Discord หรือไฟล์

`src/members/member-service.js` เป็นจุดอ่านสมาชิกที่ใช้ร่วมกับ `/ล่าสุด`; คำสั่งเดิมยังตอบ embed สาธารณะและรับคำสั่งก่อนดึงข้อมูลเหมือนเดิม เครื่องมืออ่านข้อมูลใช้สิทธิ์เดิมของบอตและไม่เปลี่ยนรูปแบบไฟล์ประวัติ ตัวอย่างคำถาม: `จีจี้ใครเข้ามาล่าสุด`, `จีจี้ใครออกล่าสุด`, `จีจี้ดูประวัติกิจกรรมยังไง`


### การค้นเว็บด้วย Google Search

ตัวอย่าง: `จีจี้ ช่วยค้นข่าวล่าสุดเรื่อง AI`, `จีจี้ อากาศกรุงเทพวันนี้เป็นอย่างไร`, `จีจี้ ค้นกำหนดการงานหนังสือครั้งถัดไป` Gemini เป็นผู้เลือกเรียก `search_google` ตามคำถามและบริบท ไม่บังคับค้นทุกข้อความ; การคุยเล่นยังตอบได้ตามเดิม และความแม่นยำ/การเลือกเครื่องมือจริงยังต้องลองกับบัญชีและโมเดลที่ติดตั้ง

- `src/jiji/gemini-client.js` ประกาศ function `search_google` ในวงจรสนทนา เมื่อโมเดลเรียกเครื่องมือจะตรวจสิทธิ์ผ่าน `src/jiji/jiji-tools.js` แล้วส่ง **เฉพาะคำค้นที่โมเดลสร้าง** ไป `generateContent` ด้วย `tools: [{google_search: {}}]` แยกคำขอ ไม่ส่งความจำหรือผลเครื่องมือ Discord เพิ่มในคำขอค้นนั้น จึงไม่ผสม built-in Search กับ function declarations ในคำขอเดียว และรองรับโมเดลเริ่มต้น `gemini-2.5-flash` ที่รองรับ Search อยู่แล้ว
- ผลสรุปที่มี grounding metadata ส่งกลับเป็น function response ให้ Gemini ตอบต่อในคำถามเดิม `src/jiji/google-search.js` ตรวจ metadata และแนบ URL อ้างอิงกับ Search Suggestions ที่ Google คืนมาโดยตรงหลังคำตอบ ไม่ให้โมเดลสร้างรายการลิงก์แทน metadata ไม่ fetch URL เหล่านี้หรือประมวลผล HTML; Discord แสดงลิงก์ข้อความแทน HTML/CSS widget (การแสดงผลจริงและข้อกำหนดของ Google ต้องตรวจตอนติดตั้ง) ไม่เพิ่ม MCP, SDK หรือแพ็กเกจใหม่
- จำกัด **หนึ่งครั้งที่เรียก `search_google` ต่อคำถาม**, คำค้นไม่เกิน 500 หน่วย UTF-16, แหล่งอ้างอิงไม่เกิน 5 URL และ Search Suggestions ไม่เกิน 5 URL; Google อาจค้นหลาย query ภายในคำขอเดียว เพดานนี้ไม่ใช่เพดานจำนวน query หรือค่าใช้จ่ายของ Google
- คงเพดานรวม **3 HTTP requests, 4 function calls และ 30 วินาที** โดยนับคำขอค้นรวมด้วย เส้นทางค้นปกติใช้ 3 requests: เลือกเครื่องมือ → Search → คำตอบสุดท้าย เครื่องมือ Discord กับ Search อยู่ใน batch เดียวกันได้ แต่ถ้าโมเดลขอ Search หลังใช้ requests ไปแล้ว 2 ครั้ง หรือขอค้นซ้ำ จะตอบ API failure เดิมโดยไม่เริ่มคำขอค้นที่เกินงบ
- ต้องมีข้อความผลค้น, `webSearchQueries`, แหล่งอ้างอิง HTTPS ที่ปลอดภัย และลิงก์ Search Suggestions ใน metadata หากขาด/ผิดรูปแบบ, แหล่งอ้างอิงเกินขีดจำกัด, Search/API ล้มเหลว หรือคำตอบรวมลิงก์เกิน 2,000 หน่วย UTF-16 จะตอบ `จีจี้เหนื่อยแล้ว 😴 รอก่อนแล้วค่อยมาคุยกันใหม่นะ` ไม่มี retry/fallback หรือเดาข้อมูลแทนผลค้น
- ไม่เก็บคำถาม/คำตอบที่ใช้ Search, ผลค้น, queries หรือ URL ลงไฟล์ความจำ/กิจกรรมหรือ logs คู่ที่ใช้เครื่องมือจึงไม่เป็นบริบทให้คำถามถัดไป; ถ้าถามต่อเรื่องผลค้นให้ระบุหัวข้อซ้ำ ข้อความที่ส่งสำเร็จยังอยู่บน Discord ตามปกติ `/ลืม`, ปิดจีจี้, ลบห้อง และปิด runtime ยกเลิก Search ที่รอและทิ้งผลล่าช้าเช่นเดียวกับเครื่องมือเดิม
- ใช้ `GEMINI_API_KEY`/`GEMINI_MODEL` เดิม ไม่มีตัวแปรใหม่ใน `.env.example` ไม่ต้องลงทะเบียนคำสั่งซ้ำ เพิ่ม permission/OAuth2 scope/intent หรือย้ายข้อมูล หยุดโปรเซสเดิมแล้วรัน `npm start` ใหม่หลังอัปเดต; ตรวจว่าโมเดลและ project ใช้ Google Search ได้ รวมโควตา/ค่าใช้จ่ายที่ [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing) บอตไม่เปิด billing หรือเปลี่ยน tier/model ให้เอง
- คำค้นถูกสร้างโดยโมเดล จึงห้ามส่งข้อมูลลับในบทสนทนา Prompt กำชับค้นเฉพาะข้อมูลสาธารณะและไม่ส่งข้อมูลสมาชิกไปค้น แต่ไม่ได้รับประกันการกรองข้อมูลส่วนตัวทุกกรณี การไม่เก็บบนเครื่องบอตไม่ใช่การลบข้อมูลจาก Google; ดู [Grounding with Google Search](https://ai.google.dev/gemini-api/docs/generate-content/google-search) และ [เงื่อนไขข้อมูลและการแสดง Search Suggestions](https://ai.google.dev/gemini-api/terms#grounding-with-google-search)

### Gemini: การตั้งค่าและความเป็นส่วนตัว

`src/jiji/gemini-client.js` ส่งคำถามและวนเรียกเครื่องมือผ่าน native fetch โดย runtime เชื่อมกับแชทที่ผ่านการตรวจสิทธิ์ ข้อมูลตั้งค่าทั้งหมดมีชื่อใน `.env.example` และเว้นค่าตัวอย่างว่าง:

| ค่าใน `.env` | จำเป็นหรือไม่ | ความหมายและแหล่งที่มา |
| --- | --- | --- |
| `DISCORD_TOKEN` | จำเป็น | Bot Token จาก Developer Portal → Bot เก็บเฉพาะ `.env` |
| `DISCORD_CLIENT_ID` | จำเป็น | Application ID จาก Developer Portal → General Information |
| `DISCORD_GUILD_ID` | จำเป็น | Server ID จาก Discord ที่เปิด Developer Mode แล้วคลิก Copy Server ID |
| `GEMINI_API_KEY` | ไม่จำเป็นสำหรับคำสั่ง Discord เดิม | สร้าง key ที่ [Google AI Studio](https://aistudio.google.com/apikey) โดยเลือกหรือสร้าง Google project แล้วเก็บเฉพาะใน `.env` ไม่ส่ง key ในแชทหรือ Git หากไม่กำหนดค่า คำสั่งเดิมยังใช้ได้; `/จีจี้ เปิด` จะแจ้งให้ตั้งค่า |
| `GEMINI_MODEL` | ไม่จำเป็น | ชื่อโมเดลจาก [รายการโมเดล Gemini](https://ai.google.dev/gemini-api/docs/models) ค่าเริ่มต้น `gemini-2.5-flash` เมื่อเว้นว่าง รับเฉพาะ identifier ที่ขึ้นต้น `gemini-` ตามด้วยอักษรอังกฤษพิมพ์เล็ก ตัวเลข จุด หรือขีดกลาง ไม่รับ URL; ตรวจว่าโมเดลนี้ใช้ได้กับบัญชีก่อนเปิดใช้ |

ค่า Discord ทั้งสามจำเป็นต่อการเริ่มบอตและลงทะเบียน ส่วน Gemini key/model ใช้ตามตารางนี้ หลังกรอกหรือเปลี่ยนค่าให้หยุดโปรเซสเดิมแล้วรัน `npm start` ใหม่ ใช้ขั้นตอนเปิดใช้จีจี้ด้านบนเมื่อติดตั้งครั้งแรก ห้ามรันบอตหลายโปรเซสกับไฟล์ข้อมูลชุดเดียวกัน

- Gemini free tier มี quota และความพร้อมใช้งานขึ้นกับบัญชี โมเดล และเงื่อนไขปัจจุบัน ตรวจ [ราคาและการใช้ข้อมูล](https://ai.google.dev/gemini-api/docs/pricing) และ [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits) ใน project ก่อนเปิดใช้งาน ไม่มีคำรับรองว่าจะฟรีตลอด ไม่มีการเปลี่ยนเป็น paid tier, retry หรือ fallback โมเดล/ผู้ให้บริการอัตโนมัติ
- จีจี้คุยหัวข้อทั่วไปและความบันเทิงได้ ไม่ได้จำกัดเฉพาะการดูแลเซิร์ฟเวอร์; การดูดวงเป็นความบันเทิง ไม่ใช่คำทำนายที่รับรองผล และการคุยทั่วไปยังอยู่ภายใต้นโยบายและข้อจำกัดของ Gemini
- คำถามปัจจุบัน ความจำผู้เรียกในห้องนั้นสูงสุด 10 คู่ที่ยังไม่หมดอายุ และผลเครื่องมือที่ใช้ (รวมชื่อ, User ID และเวลาเข้าร่วม/ออก) จะส่งไป Google Gemini ข้อมูล free tier อาจถูกใช้ปรับปรุงผลิตภัณฑ์ตามเงื่อนไข Google จึงควรแจ้งสมาชิกและไม่ส่งข้อมูลลับ อ่าน [เงื่อนไข Gemini API](https://ai.google.dev/gemini-api/terms) ก่อนเลือก tier
- โมดูลใช้ native fetch ไปยัง `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` เท่านั้น ส่ง key ผ่าน header `x-goog-api-key` และปฏิเสธ redirect ไม่สร้าง server chat session ไม่ส่ง attachment และไม่ดึงประวัติ Discord; Search ใช้ Google grounding ใน endpoint เดิมตามหัวข้อการค้นเว็บ ความจำเป็นไฟล์ท้องถิ่นตามหัวข้อที่เก็บข้อมูลสนทนา
- ต่อคำถามจำกัด 3 HTTP requests รวมคำขอ Google Search, 4 function calls (Search ไม่เกินหนึ่งครั้ง), output 512 tokens และคำตอบไม่เกิน 2,000 หน่วย UTF-16; คำตอบยาวเกินจะถือว่าล้มเหลว `src/jiji/jiji-chat.js` ส่ง AbortSignal ของ deadline รวม 30 วินาทีซึ่งครอบคลุมสิทธิ์ เครื่องมือ และ Gemini; โมดูลยกเลิกหรือทิ้งผลล่าช้า เมื่อเกิดความล้มเหลว runtime จะส่ง structured diagnostic ที่ผ่าน allowlist ไป stderr ตามหัวข้อถัดไป โดยไม่มี provider body, key หรือบทสนทนา
- provider failure รวม quota/key/HTTP/network/timeout, Search ล้มเหลวหรือ metadata ไม่ครบ, blocked/empty/malformed response และงบการเรียกหมด จะตอบ `จีจี้เหนื่อยแล้ว 😴 รอก่อนแล้วค่อยมาคุยกันใหม่นะ` โดยไม่บันทึกเป็นความจำ ส่วนการดึงสมาชิกหรืออ่านไฟล์ล้มเหลวต้องใช้ข้อผิดพลาดไทยด้านงานนั้นแยกต่างหาก

รูปแบบ request/response อ้างอิง [Gemini generateContent REST](https://ai.google.dev/api/generate-content) และ [function calling](https://ai.google.dev/gemini-api/docs/function-calling): ใช้ `parametersJsonSchema` สำหรับ schema กลาง และคง model parts รวม thought signatures เมื่อส่งผลเครื่องมือกลับ ไม่แสดง thought text เป็นคำตอบ

### การตรวจสอบข้อผิดพลาดจีจี้

เมื่อคำถามจีจี้ล้มเหลว runtime เขียน JSON หนึ่งบรรทัดต่อเหตุการณ์ไปที่ `stderr` โดยยังคงข้อความที่ผู้ใช้เห็นเหมือนเดิม ตัวอย่าง Search ตอบ HTTP 429:

```json
{"event":"jiji_turn_failed","timestamp":"2026-10-11T01:23:45.000Z","traceId":"00000000-0000-4000-8000-000000000001","stage":"google_search","category":"search_failed","httpStatus":429,"reason":"http","durationMs":812,"requestCount":2,"toolCount":1}
```

`timestamp` เป็นเวลา UTC; `traceId` เป็น UUID ที่สร้างเฉพาะคำถาม; `stage` ระบุช่วงงาน; `category` และ `reason` เป็นรหัสภายในที่ผ่าน allowlist; `httpStatus` มีเฉพาะเมื่อมี HTTP status ที่ถูกต้อง; `durationMs` คือเวลาที่ผ่านไป; `requestCount` นับ Gemini และ Search requests รวมกันสูงสุด 3; `toolCount` นับการเรียกเครื่องมือสูงสุด 4. HTTP 429 ยืนยันเพียงว่าได้รับสถานะ 429 ไม่ได้พิสูจน์ว่า key ผิดหรือ quota หมด

ความล้มเหลวที่เกิดจากผู้ดูแลล้างความจำ ลบห้อง ปิดจีจี้ หรือปิดโปรเซสจะใช้ `event: "jiji_turn_cancelled"` พร้อมเหตุผล เช่น `forgotten`, `channel_removed`, `disabled` หรือ `shutdown`; timeout จะใช้เหตุผล `provider_timeout` หรือ `turn_timeout` ตามขอบเขตที่หมดเวลา หากงานหมดเวลาเฉพาะ provider จีจี้ยังพยายามส่งข้อความเหนื่อยเดิมภายใน deadline รวม ส่วนการยกเลิกจากผู้ดูแลจะไม่ส่งคำตอบล่าช้า การปฏิเสธสิทธิ์ตามปกติและการทักทายไม่สร้าง log

Log มีเฉพาะชื่อ event, เวลา, trace ID, stage, category, reason, HTTP status และตัวนับที่จำกัดค่า ไม่เก็บชื่อหรือ ID ของ Discord, ข้อความ/ประวัติสนทนา, prompt, คำตอบ, คำค้น/URL, ข้อมูลเครื่องมือ, provider body, error message/stack, key หรือ headers การเก็บไฟล์และการหมุน/ลบ log เป็นหน้าที่ผู้ดูแล แอปไม่สร้างไฟล์ log ใน `data/` และไม่จัดการ retention ให้

บนเครื่องที่ต้องการเก็บ log ให้รัน:

```sh
mkdir -p logs
npm start 2>>logs/jiji-errors.log
```

ไฟล์นี้รับ stderr ทั้งหมดของโปรเซส ซึ่งอาจมีข้อความอื่นนอกเหนือจาก Jiji diagnostics; ผู้ดูแลเป็นผู้กำหนดการหมุนเวียนและลบไฟล์ โฟลเดอร์ `logs/` ถูกละเว้นโดย Git

หลังติดตั้งเวอร์ชันที่มีการเปลี่ยนแปลงนี้ ให้หยุดโปรเซสเดิมแล้วรัน `npm start` ใหม่ ไม่ต้อง `npm run register`, เพิ่มค่า `.env`, เปลี่ยน permission/intent หรือย้าย/migrate ข้อมูลเดิม `gemini.respond` ส่ง progress ภายในเฉพาะ `{ stage, requestCount, toolCount }`; Search/tool failure ส่ง metadata ภายใน `{ stage, reason, status? }` และตัดออกก่อนส่ง function response กลับ Gemini

| `จีจี้ ช่วยค้นข่าวล่าสุดเรื่อง AI` หรือ `จีจี้ อากาศกรุงเทพวันนี้เป็นอย่างไร` | Gemini เลือกใช้ `search_google`; ตอบพร้อม URL อ้างอิงและ Search Suggestions จาก Google ไม่เก็บคู่นี้ลงความจำ หากค้นไม่สำเร็จใช้ข้อความ API failure เดิม | เงื่อนไขห้องและสิทธิ์เดียวกัน |
| `จีจี้ วันนี้เหนื่อยมาก` หรือข้อความคุยเล่นอื่น | ตอบแบบแชทสั้นประมาณ 1–2 ประโยค ไม่ใส่อีโมจิเป็นค่าเริ่มต้น ใช้บ้างเมื่อเข้ากับอารมณ์หรือบริบท | เงื่อนไขห้องและสิทธิ์เดียวกัน |
| `จีจี้ อธิบายวิธีใช้ /กิจกรรม ให้หน่อย` หรือคำถามข้อมูลอื่น | ตอบครบตามที่จำเป็นและความละเอียดที่ขอ ไม่จำกัดไว้ที่ 1–2 ประโยค; คำถามกิจกรรมใช้เครื่องมือแนะนำคำสั่งส่วนตัว | เงื่อนไขห้องและสิทธิ์เดียวกัน |
| `จีจี้ดูดวงวันนี้ให้หน่อย` | คุยเรื่องบันเทิงได้; ดูดวงเป็นคำตอบเพื่อความสนุก ไม่รับประกันผล | เงื่อนไขห้องและสิทธิ์เดียวกัน |

- สไตล์คำตอบจาก Gemini ใช้ภาษาธรรมชาติเหมือนคนแชทกัน คุยเล่นตอบสั้น ไม่ใช้หัวข้อ/รายการโดยไม่จำเป็น และไม่เสนอความช่วยเหลือหรือถามต่อท้ายทุกครั้ง เช่น `จีจี้ วันนี้เหนื่อยมาก` อาจตอบ `วันนี้เจออะไรมา เล่าให้ฟังได้นะ` ตัวอย่างและจำนวนประโยคเป็นแนวทางให้โมเดล ไม่ใช่คำตอบตายตัวหรือการตัดคำตอบ; คำถามข้อมูลยังตอบได้ยาวขึ้นภายในขีดจำกัดเดิม ข้อความทักทาย รอ และ API failure ที่กำหนดตายตัวยังคงมีอีโมจิตามที่ระบุ
- หลังอัปเดตสไตล์ ให้หยุดโปรเซสเดิมแล้วรัน `npm start` ใหม่ ไม่ต้องลงทะเบียนคำสั่งซ้ำ เพิ่มตัวแปร `.env` เปลี่ยนสิทธิ์/intent หรือย้ายข้อมูล ความจำเดิมยังใช้ได้ตามกติกาเดิม; ใช้ `/ลืม` ในห้องนั้นได้หากต้องการเริ่มบทสนทนาใหม่ การทดสอบออฟไลน์ตรวจคำสั่งสไตล์ที่ส่งให้โมเดล ส่วนโทนและความยาวคำตอบจริงต้องลองคุยหลังรีสตาร์ต
- ตอบสาธารณะในห้อง ไม่ใช่ ephemeral และปิด mentions ทั้งผู้ใช้ role everyone และการ ping เจ้าของข้อความที่ reply; คำสั่งควบคุม `/จีจี้` และ `/ลืม` ยังตอบเห็นเฉพาะผู้เรียก ไม่เรียกจาก DM, thread, webhook, บอต, เซิร์ฟเวอร์อื่น หรือข้อความทั่วไปที่ไม่มี trigger ชื่อ `จีจี้` กลางข้อความไม่เรียกบอต
- Reply ต้องเป็นข้อความของบอตนี้เท่านั้น ใช้ author ที่ Discord ส่งมาก่อน หากไม่มีให้ดึงเพียงข้อความอ้างอิงหนึ่งข้อความเพื่อดู author โดยไม่อ่านเนื้อหา ไม่ดึงประวัติแชทและไม่ใช้ attachment หากอ้างอิงหาย ดึงไม่ได้ หรือเป็นข้อความของผู้อื่นจะไม่เดา; ชื่อที่ต้นข้อความหรือ mention ยังเรียกได้โดยไม่ต้องดึง reference
- รีเฟรชห้อง roles สมาชิกผู้เรียกและสมาชิกบอตจาก Discord ก่อนอ่านความจำ ใช้เครื่องมือ และส่งคำตอบ ตรวจ settings อีกครั้งหลังงานช้า หากห้องปิด ถูกลบ ออกจากรายชื่อ หรือเข้าถึงไม่ได้จะเงียบ รวมถึงกรณีดึงข้อมูลเพื่อตรวจสิทธิ์ครั้งแรกไม่สำเร็จ เพราะยืนยันสิทธิ์ส่งข้อความไม่ได้ หากตรวจสิทธิ์ได้แล้วแต่เครื่องมือดึงสมาชิกทั้งหมดไม่สำเร็จ จะตอบ `ดึงข้อมูลสมาชิกไม่สำเร็จ กรุณาตรวจสอบ Server Members Intent แล้วลองอีกครั้ง` ไม่แสดง cache บางส่วนเป็นรายชื่อครบ
- สมาชิกคนเดียวถามได้ทีละคำถามทั้งเซิร์ฟเวอร์ และเว้นอย่างน้อย **5,000 ms ระหว่างเวลาเริ่ม** แม้ย้ายห้อง คำถามซ้อนหรือเร็วเกินตอบ `จีจี้กำลังคิดอยู่ 😊 รอแป๊บนะ` โดยไม่เรียก Gemini และไม่เก็บความจำ ไม่ต่อคิวหรือ retry คำถาม/คำตอบจำกัด 2,000 หน่วย UTF-16; คำถามยาวเกินขอให้ย่อ ส่วนคำตอบยาวเกินใช้ข้อความ API failure ด้านล่าง
- จำกัดงานทั้งหมด **30,000 ms** นับก่อนตรวจสิทธิ์ครั้งแรก รวมดึง reference, ความจำ, เครื่องมือ, Gemini และการตรวจสิทธิ์/ส่งข้อผิดพลาด ยกเลิก Gemini ที่ 29,000 ms เพื่อเหลือไม่เกินหนึ่งวินาทีสำหรับส่งข้อผิดพลาดหลังตรวจสิทธิ์ใหม่ ไม่ต่อ deadline หากหมดเวลารวมก่อนส่งได้จะเงียบและปล่อยล็อก งาน Discord ที่ยกเลิกไม่ได้และกลับมาทีหลังจะถูกทิ้ง
- ทุก Gemini API failure ใช้ข้อความเดียว `จีจี้เหนื่อยแล้ว 😴 รอก่อนแล้วค่อยมาคุยกันใหม่นะ` เมื่อยังตรวจสิทธิ์ส่งได้ ข้อผิดพลาดอ่าน/บันทึกความจำและประวัติการออกใช้ข้อความไทยด้านไฟล์แทน หากส่งคำตอบแล้วบันทึกความจำล้มเหลว จะแจ้งว่าอ่านหรือบันทึกความจำไม่สำเร็จ ไม่อ้างว่าคำตอบถูกเก็บไว้
- บันทึกเฉพาะคู่ข้อความธรรมดาที่ตอบสำเร็จ ไม่มีการเรียกเครื่องมือใด และยังไม่ถูกยกเลิก แยกตามห้อง/สมาชิก เก็บสูงสุด 10 คู่ หมดอายุเมื่อไม่มีคู่ใหม่ 30 นาทีตามหัวข้อที่เก็บข้อมูล; ไม่บันทึก tool calls/results, คำทักทาย, busy/cooldown หรือข้อผิดพลาด `/ลืม`, ลบห้อง และปิดจีจี้ยกเลิกงานที่รอทันที รวมการอ่านความจำและการเรียก Gemini ป้องกันไม่ให้เริ่มส่งคำตอบล่าช้าหรือเขียนความจำกลับหลังล้าง ข้อความที่เริ่มส่งให้ Discord ก่อนยกเลิกอาจส่งสำเร็จแล้ว; การล้างไม่ลบข้อความ Discord หรือข้อมูลที่ส่งให้ Gemini แล้ว

จีจี้เปิด Message Content Intent ในโค้ดแล้ว ผู้ติดตั้งต้องเปิดสวิตช์ใน Developer Portal ตามขั้นตอนด้านบน ใช้ `Read Message History` เดิมเฉพาะ fallback ดู author ของ reply หนึ่งข้อความ พร้อมสิทธิ์ `View Channel` ของผู้เรียก/บอตและ `Send Messages` ของบอต ไม่ต้องเพิ่ม `Administrator`, `Manage Server` ให้บอต หรือ `View Audit Log` เพื่อสนทนา


### การตรวจรับใน Discord และ Gemini

การทดสอบอัตโนมัติใช้ Discord/fetch จำลองและไฟล์ JSON ชั่วคราว ไม่ยืนยันค่าจริงในเซิร์ฟเวอร์หรือบัญชี Google หลังตั้งค่าต้องตรวจ key/model กับบัญชี, intent ใน Portal, สิทธิ์ผู้ดูแล/สมาชิก, ห้องที่อนุญาต/ไม่อนุญาต, เรียกชื่อ/mention/reply, ความจำหลังรีสตาร์ตภายใน 30 นาที, `/ลืม`/ปิดระหว่างคำถามที่รอ และคำตอบข้อมูลสมาชิก/การออกเทียบ Slash command รวม Google Search ในคำถามล่าสุด/คำขอค้นเว็บ ตรวจ URL อ้างอิงและ Search Suggestions ใน Discord, model/โควตา/Search billing ตามบัญชี, คุยทั่วไปยังตอบได้, ไม่เก็บคู่ที่ค้นเว็บ และ `/ลืม`/ปิดขณะ Search รอ ตรวจว่า mentions ไม่ ping และคำแนะนำกิจกรรมพาไปคำสั่งส่วนตัว การจำลอง API failure ใช้ fixture ออฟไลน์ ไม่จงใจใช้ quota ให้หมดเพื่อทดสอบ ขั้นตอนจริงเหล่านี้ยังต้องตรวจหลังติดตั้ง
