# Discord Welcome Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let server managers choose a welcome channel and message through Discord and welcome new human members automatically.

**Architecture:** Keep existing join activity recording unchanged. Separate durable settings, welcome message construction/delivery, and slash-command handling; wire them into the existing client. Persist settings atomically and require current permissions before configuration or delivery.

**Tech Stack:** JavaScript ES modules, Node.js >=20.6.0, existing discord.js 14.27.0, node:test, node:fs/promises; no additional dependencies.

**Spec:** [Welcome configuration design](../specs/2026-10-10-welcome-design.md). Read it and project `AGENTS.md`/`README.md` before execution. The spec records the conversational requirements and defaults for review alongside this plan.

## Global Constraints

- Keep the existing `guild_join` activity tracking and 30-day retention.
- No new intents, OAuth scopes, environment variables, dependencies, or bot-wide Manage Server permission.
- Default template when `ข้อความ` is omitted: `ยินดีต้อนรับ {member} เข้าสู่เซิร์ฟเวอร์ 🎉`.
- Accept 1–1,000 UTF-16 code units after trimming; reject whitespace-only templates.
- Final messages must be at most 2,000 UTF-16 code units, including repeated placeholder expansions.
- Only the joining user may be mentioned; role mentions and everyone/here pings are suppressed.
- One process per data file. Back up `data/` when moving installations.
- Preserve existing version 1 departure/activity data contracts and separate modules.
- Acknowledge interactions before slow work; Thai replies and secret-free diagnostics.
- Every shipped feature change includes its usage/setup documentation in the same change.

## Review Focus

- Disk write/rename failure: setup must not confirm success or change active settings; subsequent updates must recover (Task 1).
- Repeated placeholders: expanded output must fit Discord's 2,000-character limit (Task 2, validated on setup through Task 3).
- Channel deletion or changed permissions: skip delivery and keep settings; do not expose hidden settings in `/ต้อนรับ ดู` (Tasks 2–3).
- Command permission overrides or forged guild context: runtime Manage Server/guild checks must prevent reads and mutations (Task 3).
- A failing welcome send: existing join activity still records independently, with no unhandled rejection (Task 3).

Create `src/welcome-settings.js` (versioned settings store), `src/welcome-message.js` (format/validation and channel delivery), `src/welcome-command.js` (command metadata/handling), `src/member-join.js` (event orchestration and handler registration); matching tests in `test/welcome-settings.test.js`, `test/welcome-message.test.js`, `test/welcome-command.test.js`, `test/member-join.test.js` and integration tests in `test/welcome-integration.test.js`.
